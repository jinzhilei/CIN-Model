# CIN-Model

Analysis code for the manuscript **"Integrating Mathematical Modeling and Machine Learning for Chemotherapy-Induced Neutropenia Risk Stratification and G-CSF Optimization"** (Qu Y, Ning B, Li C, Zhuge C, Wang M, Zou X, Lei J, Wei Y; working version V01, revised November 2026).

This repository is a snapshot of the code used to fit the mechanistic model and to draw the figures. It contains MATLAB code for the delay differential equation (DDE) model, particle swarm optimization (PSO) parameter fitting, pharmacokinetic (PK) profiles, Morris global sensitivity analysis and figure panels, and R code for the statistical comparisons, the random forest classifier and the expert survey. The manuscript LaTeX source and the journal figure PDFs are not part of this repository; the PNG panels generated by the scripts are included.

The code availability statement in the manuscript points to `https://github.com/jinzhilei/CIN-Model`.

---

## What the code does

The model tracks four state variables: quiescent hematopoietic stem cells `Q`, neutrophils in the bone marrow reservoir `M`, circulating neutrophils `N`, and a bone marrow microenvironment (BMM) index `E` (called `P` in the MATLAB code). It is a system of DDEs with fixed delays for HSC division (`tau_s = 2.8 d`) and neutrophil proliferation plus maturation (`tau_n = tau_p + tau_m = 11 d`). Capecitabine and G-CSF enter through PK/PD terms: a one-compartment first-order absorption/elimination model for capecitabine and a two-compartment model with nonlinear elimination for G-CSF.

Twelve parameters are fitted per patient by minimizing the symmetric mean absolute percentage error (sMAPE) between simulated and observed absolute neutrophil counts (ANC), using `particleswarm` with a swarm of 30 and 20 iterations. The fitted BMM trajectories give the composite injury metric `E_injure`, and Ward clustering on that metric splits 30 patients into Moderate (n = 17) and Severe (n = 13). A random forest trained on baseline clinical variables with leave-one-out cross-validation predicts the cluster label. Finally, G-CSF schedules with `n = 1, 2, 4` injections at intervals `tau = 1, 2, 3` days are compared under a fixed total dose.

Numerical conventions that matter when reading the code:

| Item | Convention in the code |
|---|---|
| Time unit | Hours (`dt_hours = 0.1 h`); paper tables quote rates per day, so parameters are divided by 24 and delays multiplied by 24 |
| ANC units | Clinical data in `10^9 cells/L` are divided by 1.4 to give `10^8 cells/kg` (5 L blood, 70 kg body weight) |
| CTCAE thresholds | Grade 2 `1.0 x 10^9/L` = `0.714` in model units; `0.5 x 10^9/L` = `0.357` |
| BMM state | `E` in the manuscript, `P` or `phi` in the MATLAB code; `E_0 = 1`, initial value `0.9` |
| G-CSF half-saturation constants | `B_s = B_m = B_v` are merged into `par(8)`; `B_n` is `par(9)` |
| Simulation horizon | 19 cycles of 21 days: 15 drug-free warm-up cycles, one drug-exposed cycle before the observation window, then 3 analysed cycles. `C_cap`/`C_csf` are zeroed for the first 315 days |
| Dosing times in code | Capecitabine twice daily on days 1-14 of each cycle (dose times 24-336 h after cycle start) and one G-CSF injection of 200 ug at hour 48. Some copies of the PK function label the same dose times as "days 2 to 15" with a `(day-1)*24` offset; the two loops give identical dose times. Clinical day 0 (the first ANC sample) is aligned to simulation day 336 = (15 + 1) x 21 |
| Observation times | Six ANC samples per patient, at days 0, 4, 21, 25, 42, 46, as stated in the Methods section |

## Requirements

**MATLAB.** The manuscript used R2024a. Minimum practical version is R2022a because `main_Figure_8F.m` calls `clim`; `exportgraphics` requires R2020a or later. Required toolboxes:

- Global Optimization Toolbox (`particleswarm`, `optimoptions`)
- Parallel Computing Toolbox (`parfor`, `parpool` in `Main_model/main_PSO.m`)
- Statistics and Machine Learning Toolbox (`pdist`, `linkage`, `cluster`, `boxplot`, `ranksum`, `kruskalwallis`, `ksdensity`, `corr`, and `lhsdesign` in the Morris sampling code)

**R.** The manuscript used R 4.5.2. Packages by script:

| Script | Packages |
|---|---|
| `Figure_4/Figure_4A/main_Figure_4A.R` | ggplot2, dplyr, tidyr, gghalves |
| `Figure_4/Figure_4C/main_Figure_4C.R` | tidyverse, gghalves |
| `Figure_6/RFmodel-LOOCV-30aver_Newdata.R` | readxl, dplyr, caret, randomForest, pROC, ggplot2, rms, Boruta |
| `Figure_7/Figure_expert.R` | tidyverse, readxl, ggtext, magrittr, ggprism, MetBrewer, plotly |
| `Figure_S2/main_Figure_S2.R` | tidyverse, ggpubr |
| `Figure_S3/Mantel_Test.R` | linkET, ggplot2, ggtext, dplyr, RColorBrewer, cols4all, tidyverse |

`linkET` may need to be installed from its GitHub repository rather than CRAN. Each R script now records the R version and package names in a header comment, but package versions are not pinned by a lock file; record `sessionInfo()` if exact reproduction is needed.

```
Main_model/             Core DDE model, PK profiles, PSO fitting, single-patient demo
Sensitivity Analysis/   Morris global sensitivity analysis: sampling, mu/sigma, ranking plot
Figure_2/               Clinical ANC trajectories
Figure_3/               Individual model fits for patients 1-30
Figure_4/               BMM injury metric and patient stratification (4A/4C in R, 4B in MATLAB)
Figure_5/               Cohort comparisons (5A-5D)
Figure_6/               Boruta feature selection + random forest LOOCV (R)
Figure_7/               Clinical expert Likert survey (R)
Figure_8/               Cycle-wise progression and G-CSF schedule comparisons
Figure_S1/              PK model fitting to published concentration data
Figure_S2/              Observed versus predicted ANC (R)
Figure_S3/              Parameter correlations and Mantel test (R + MATLAB)
Figure_S4/              Population-average fit and Morris sensitivity ranking
Figure_S5/              Circular clustering dendrogram
Figure_S6/              Cohort ANC distributions at cycle starts
```

Figure 1 is a schematic of the study design and has no code. Each `Figure_*` directory is self-contained: the model and PK functions are copied into the directories that need them, and all paths are relative to the directory of the entry script. **Run every script from its own directory** (for example `cd Figure_3` before `main_Figure_3`). Every main figure script writes a 300-dpi PNG into a `Figure/` subdirectory of its own directory; 27 such PNGs are shipped with the repository.

## Quick start

Clone the repository, then run scripts from their own directories.

MATLAB, refit all 30 patients (long run, opens a parallel pool):

```matlab
cd 'Main_model'
main_PSO            % writes PSO/params_1.mat ... params_30.mat and params.mat
```

MATLAB, reproduce one fitted trajectory with the stored parameter set:

```matlab
cd 'Main_model'
main_simulation     % patient 1 by default; change parameter_index in the file
```

MATLAB, one figure panel:

```matlab
cd Figure_3
main_Figure_3
```

MATLAB, regenerate the Morris sensitivity indices (310 model evaluations, long run):

```matlab
cd 'Sensitivity Analysis'
main_Morris         % writes output/mu.mat and output/sigma.mat
main_Figure_Morris
```

R, one figure panel:

```r
setwd("Figure_6")
source("RFmodel-LOOCV-30aver_Newdata.R")
```

All main scripts save their panels as PNG. Running them again overwrites the shipped PNG of the same name.

## Data

| File | Content |
|---|---|
| `Data_neutrophil.mat` (copies in `Main_model`, `Figure_2`, `Figure_3`, `Figure_5/Figure_5A`) | ANC measurements, 30 patients x 6 time points (days 0, 4, 21, 25, 42, 46), in `10^9 cells/L` |
| `PSO/params*.mat` | Fitted 12-parameter vectors, one per patient, plus cohort-average and population-average sets |
| `Figure_S3/patient_12parameters.csv` | The same 12 parameters in tabular form, `P1` ... `P30` |
| `New_Eindex.csv` (copies in `Figure_4/Figure_4A`, `Figure_4/Figure_4B`, `Figure_S5`) | BMM state at day 0 (`y0`) and day 63 (`y1`) for 30 patients |
| `Figure_4/Figure_4C/neutrophil_time_series.csv` | ANC at six time points for `patient_1` ... `patient_30` |
| `Figure_S2/y_obs.csv`, `y_pred.csv` | Observed and model-predicted ANC, 30 x 6, used for the fit-validation scatter plot |
| `Figure_6/data_Newcluster.xlsx` | 22 baseline clinical variables, one row per patient, plus the cluster label |
| `Figure_7/Clinicalexpert.xlsx` | 8 experts x 8 questions, 5-point Likert scores |
| `Figure_8/Data_AB/*.mat`, `Figure_5/Figure_5C/duration_n1_taut1.mat`, `Figure_S4/GSA/mu.mat`, `Figure_S6/ANC*.mat` | Precomputed simulation summaries used by the figure scripts |
| `Sensitivity Analysis/output/mu.mat`, `sigma.mat` | Morris indices produced by `main_Morris.m`; these are separate from `Figure_S4/GSA/mu.mat`, which is the file read by `main_Figure_S4B.m` |

The injury metric is computed from `New_Eindex.csv` as `I_initial = 1 - y0`, `I_chemo = y0 - y1`, each min-max normalized across the cohort, then combined with weights `w1 = w2 = 0.5`. Ward linkage on this score with two clusters reproduces the 17/13 split. The Severe patient indices used in several scripts are `[1, 2, 3, 5, 7, 8, 12, 13, 19, 22, 24, 25, 30]`; all remaining indices are Moderate.

The two six-element vectors in `Figure_5/Figure_5B/Data.m` and the one in `Figure_S4/Data.m` are cohort and population means already expressed in model units (`10^8 cells/kg`). They are hard-coded rather than recomputed from `Data_neutrophil.mat`; the values reproduce the group means of the 30-patient matrix after dividing by 1.4.

Individual IDs are pseudonyms (`P1` ... `P30`, `patient_1` ... `patient_30`). No names, hospital numbers, dates of birth or contact details are included. The baseline table in `Figure_6/data_Newcluster.xlsx` still combines age, sex, TNM stage and laboratory values at the individual level, which makes it a quasi-identifiable dataset. Check the ethics approval (Zhongnan Hospital of Wuhan University, No. 2025056) and your institution's data-sharing agreement before making that table public in a public repository; if needed, replace it with a de-identified or synthetic version and document the change here.

`.Rhistory` files and macOS `.DS_Store` files are excluded by `.gitignore`. They contain local working-directory paths and, in two cases, hand-copied patient-level values, and should not be committed. Make sure `.gitignore` itself is committed: without it these files are picked up by `git add .`.

## Known issues

This is the exact snapshot used for the submitted figures, not a cleaned end-to-end pipeline. The following issues are documented so that anyone reusing the code can judge which results are reproducible from source.

1. **Missing generators for precomputed results.** No script in this repository produces `Figure_8/Data_AB/Durations.mat`, `Nadir.mat`, `Figure_8/Result/Grouped_Stats_Matrices.mat` or `Figure_5/Figure_5C/duration_n1_taut1.mat`. The `n x tau` G-CSF dose-grid simulation that underlies Figures 5C and 8 is not included. A Morris sampling script is now provided in `Sensitivity Analysis/`, but it writes to `output/` and is not wired to `Figure_S4/GSA/`.
2. **Figure 8F cannot run on the shipped data.** `main_Figure_8F.m` requires four variables in `Grouped_Stats_Matrices.mat`, but the file contains only `ANC_Moderate_Mat` (3 x 3). The shipped `Figure/Figure_8F.png` was produced from a more complete version of that file.
3. **Cohort means are hard-coded.** Figure 5B and Figure S4A read their observed mean ANC from literal vectors in `Data.m` rather than from the 30-patient matrix. The units are correct, but the values will not follow a change to the input data.
4. **Statistical and modelling details.** `Figure_2/Fig_ANC_low.m` applies an independent-sample Kruskal-Wallis test to repeated measurements from the same patients. The random forest script selects the eight features with the highest Boruta `meanImp` rather than only the Confirmed set, uses `mtry = sqrt(8)` without rounding, and runs a single LOOCV pass despite its `30aver` filename. Figure 5A and Figures 8C,D report no formal test. The correlation annotated on the S2 plot is computed on the linear scale, whereas the manuscript reports the log-transformed value.
5. **Randomness.** The PSO initial swarm in `Main_model/main_PSO.m`, the jitter in `Figure_5/Figure_5D/main_Figure_5D.m`, and the Latin hypercube base points in `Sensitivity Analysis/radial_sampling_method_multi_output.m` are not seeded, so those results change between runs. Seeds are set in the Mantel test, Figures 4A, 4C and 5C, and the Boruta and forest fits. Stored `PSO/params*.mat` files and the shipped `mu.mat` are therefore the authoritative results.
6. **Morris implementation.** The sampling code is a standalone implementation with its own copy of the model and solver, a different parameter interface, an initial BMM value of 1 (versus 0.9 in the fitting code) and 20 simulated cycles (versus 19). Each trajectory perturbs one coordinate of a common base point, and the step size `delta` defined in the sampler is not used when the effects are computed; `sigma` is the standard deviation of the absolute effects. Its output is not numerically identical to `Figure_S4/GSA/mu.mat`. Anyone interpreting individual parameter rankings should first regenerate them with the fitting model in `Main_model/`.
7. **Output and portability.** `Figure_S1/picture_PK.m` uses `Figure\...` with a Windows separator for one of its two panels, which on macOS/Linux creates a file whose name contains a backslash; its PK observations are hard-coded in the plotting script. Three other PK copies label the dosing loop as days 1-14 and two as days 2-15, although the dose times are the same.
8. **Leftovers from earlier versions.** Duplicated model files across figure directories, the `G1`/`G2` group labels in `Figure_4/Figure_4C/main_Figure_4C.R` (the comment defines 1 = Severe, 2 = Moderate), old panel identifiers such as `main_Figure_E5B` in `Figure_S4/main_Figure_S4B.m`, the unused `ANCtrue.mat` load in Figure S6, and `Figure_S4/Result/Figure_E5B.png` are remnants and should be read as such. Figure 1 has no generating script.
9. **Console noise.** `Main_model/main_PSO.m` (line 41), `Main_model/pso_objective.m` (line 63), `Main_model/Data.m` (line 23) and several `Sensitivity Analysis/` scripts are missing trailing semicolons, so a full PSO run prints the objective value at every evaluation.
